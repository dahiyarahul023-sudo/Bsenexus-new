# Filing edge cache staging candidate

- Start: `101482f68aa8e53c26dd6c5e06c289db0450650f`. The live Worker currently uses a 30-second cache for anonymous filing reads. Requests still invoke the Worker, even when its Cache API returns a hit.
- Candidate: `ops/cloudflare/filing-cache.mjs` caches successful public JSON for the exact filing list route for six seconds at the edge. Browser responses require revalidation. Origin headers, including the BSE feed delay indicators, remain available. Signed-in, conditional, range and non-GET requests pass through. Cache failures fall back to the origin. No production route imports the candidate.
- Impact review: `npm run map:impact -- server/api/routes.ts src/components/Announcements.tsx src/api.ts` was run. These are the request producer and consumer, including the feed refresh and health display. The gateway has its own deployment. Alert delivery, ingestion and database writes remain independent of the candidate.
- Staging integration: on an isolated BSE Nexus Worker, import `fetchFilingFeed` and call it for the filing list with `caches.default`, the existing origin fetch and `ctx.waitUntil.bind(ctx)`. Leave the other routes on the existing handler. Serve only public build assets directly through static asset routing. Keep API and SSR routes on the Worker and keep the server bundle out of the static asset directory.
- Acceptance in staging: compare 30-second and 6-second policies using matched traffic. Check publish-to-browser p50/p95, origin requests, Worker invocations, and source-delay headers. Verify that static asset requests bypass Worker code and that signed-in, query-filtered and error responses behave as expected. The six-second policy optimizes freshness. Static serving and reduced polling address the Worker request budget.
- Validation: `node --test ops/cloudflare/filing-cache.test.mjs` exercises the candidate with fake origin and cache. The hosting account has production custom domains but no verified BSE Nexus staging Worker. Remote staging and live rollout remain pending. Roll back by keeping or restoring the previous Worker version and routing.
