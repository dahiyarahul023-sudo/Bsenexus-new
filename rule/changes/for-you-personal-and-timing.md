# For You watchlist ownership and historical result filing times

- Starting main: 3cfaff13b932a100a1cf90ce8e928e359050d000. Source restored from byte-identified main files after scratch cleanup; prior PR 30/31 changes retained.
- User objective: Add Stock chooses an existing watchlist or creates one inline; membership is per selected list. Every For You data section follows active watchlist identities; no unrelated market fallback. Today distinguishes declared results from awaited filings. Results tool shows historical filing-time concentration and explicit exceptions.
- Existing owners reviewed: HomeForYou watchlists + watchlists-changed event; guarded POST /watchlists and /watchlists/:id/symbols; search-company; activeWatchlistIdentities/matchesWatchlistIdentity; HomeNewsFeed generation guards; Radar feed; shared ADR identity registry; Story company subjects/list-item identities; canonical quarterly ledger declaration timestamps.
- Changes: explicit target/create form with confirmed feedback, synchronous mutation lock, owner/unmount guards and timeout (no auto mutation retry). Existing server authorization/plan limits remain. Stock search uses existing resolver API; newly created list is retained if adding its stock subsequently fails, preventing repeated creation on retry.
- Home results request watchlist scope, filter exact identities before the four-card limit, include today declarations and future seven-day meetings. News, Radar, ADR and Stories use opt-in strict projections; standalone/global defaults remain. Company-name terms support news titles; short ticker substrings never match. Unknown/error/empty watchlists do not fall back to market data.
- Timing: first verified declaration per quarter, latest eight timed quarters, IST. At least four observations required for a usual window. A 60-minute window is preferred, then 120 minutes, only when at least 75% and at least three observations fit; remaining points are exceptions. Circular midnight windows supported. Scheduled meeting clocks, ingestion timestamps, missing date-only values and future records are excluded. Graph/table labels explain historical evidence rather than promised future release.
- Related consumers: Calendar and Company Hub share QuarterlyResultsLedger/ResultTimingPanel; Home and Calendar have distinct declared-today labels/accent. News/Story/Radar standalone readers retain their existing global scope unless explicitly personalized. ADR global data stays shared, while Home shows only watched supported companies.
- Refresh readers: WatchlistManager emits its existing event with a source marker, ignores its own read notification and reloads external membership changes. Calendar reloads its list options and its watchlist-scoped dates; App reloads the NewsPortal watchlist projection. All touched reads cancel superseded requests and bind results to the current account. This prevents a previously visited retained tab from keeping the pre-add list. Cross-tab windows are not synchronized by this same-window event.
- Recovery: malformed watchlist responses clear Home personal previews, rather than retaining a previous projection under an unknown membership state. Timing has an explicit unavailable state. Add feedback restores dialog focus after the focused Add button becomes disabled, so Escape/Tab remain usable.
