# Watchlist refresh, card controls and version labels

- Starting commit is `c6fcef7e9ebfb32baa42924e74cb6315bdbb5f57` on `main`.
- The objective is a discoverable Watchlist refresh, distinct failure and success feedback, usable card controls on small screens, less Settings chrome and a short public version label.
- In `WatchlistManager`, the old quick refresh awaited two read helpers that handled errors internally, then issued a success toast. The new refresh checks both outcomes, prevents repeated manual reads, guards against an account switch, and shows a retry with the previous list still on screen. A visible Refresh action, Retry, and pull use the same handler. Foreground Watchlist evidence keeps its existing interval. The unused full manual sync branch was removed.
- In `usePullToRefresh`, a failed or skipped refresh returns false and suppresses success vibration. A gesture can cross the threshold without replaying a tick during the same pull. `triggerThresholdTick` uses supported vibration only. Existing callers that return void keep their current completion behavior. A separate audit of those callers' error handling is pending.
- Company cards make ordinary actions neutral and expose the priority, filing count and destructive action with text or accessible names. Touch controls are larger. The add-company disclosure has an accessible name and expanded state.
- The app and public landing footer show the shared version with full metadata one press away. Settings hides its extra header shortcut when its screen is open and leaves the desktop navigation entry in place. Settings removes the static security assurance badge and describes logs as on demand. The separate footer security entry serves the wider admin role and stays available.
- Source trace covered the announcements and Watchlist reads, account cache, `watchlists-changed`, Watchlist filing counts, Company Intelligence entry, App shell, landing, pull-to-refresh consumers and Settings. Existing filing ingestion, role gates, note flows, and backend API contracts need no deployment migration for this patch.
- The repository impact function was run against the pinned map in JavaScript. The application and landing reverse imports intersect navigation, design, identity and public surfaces. The gesture change also reaches the Announcements and News/Calendar consumers through shared imports or browser events. No semantic domain membership changed.
- The mobile browser fixture now covers a failed feed refresh, preservation of the loaded company row, retry, and a 44px priority control at 360px and 390px. It uses synthetic providers. This turn had no usable executor for running Playwright or npm locally. GitHub CI checks source-map freshness and application builds independently.
- Still to verify in a browser are the Settings Back and focus path, the real note button inside the card, actual contrast pairs, iPhone Safari, Android Chrome/PWA and desktop behavior. The new in-repo skills capture the color and feedback checks for successive passes. No device haptic measurements or production freshness measurements were taken.
- Rollback is a frontend Git revert and republish. No schema or data migration is included. Commit, merge, checks and production publish are separate delivery states.
