# Color review

1. Start with the actual screen, role and supported states. Find the shared primitive or token before touching a local class. Compare both themes at a phone width and desktop width.
2. Assign one job to each color. Use neutral ink for ordinary stock actions and personal priority labels. Keep active selection, verified market outcomes, high-impact filings and destructive controls distinguishable. A user's priority cannot establish filing impact. Pair meaningful color with visible text or an icon with an accessible name.
3. Measure actual foreground/background combinations including transparency over the rendered surface. Target WCAG AA at 4.5:1 for normal text and 3:1 for large text and meaningful UI boundaries. Check resting, focus, pressed, hover, failed, and disabled states. Remove decorative accent badges before introducing another color.
4. Use subtle surface changes on press. Keep dense data cards legible on an opaque surface. Check blur or depth effects where they serve a real layer, including scrolling and Reduced Motion.
5. Record screenshots by state and theme, measured contrast pairs, affected tokens and any gaps. Use text and shape to test that the journey is understandable with color removed.

References are [Apple HIG Color](https://developer.apple.com/design/human-interface-guidelines/color) and [WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
